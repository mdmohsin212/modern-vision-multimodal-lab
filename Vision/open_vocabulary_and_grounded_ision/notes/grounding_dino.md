# Study Notes: Open-Vocabulary Object Detection with Grounding DINO

## ১. মূল ধারণা: Traditional YOLO vs. Grounding DINO

| বিষয় | Traditional YOLO | Grounding DINO |
| --- | --- | --- |
| **Class Architecture** | Fixed class list (ট্রেনিংয়ের নির্দিষ্ট চেকেপয়েন্টে সীমাবদ্ধ)। | Open-vocabulary (জিরো-শট সুবিধাসহ টেক্সট প্রম্পট দিয়ে অবজেক্ট খোঁজা যায়)। |
| **Input Feature** | শুধুমাত্র ইমেজ (Image)। | ইমেজ + টেক্সট প্রম্পট (Image + Text Prompt)। |
| **Adaptability** | নতুন অবজেক্ট টাইপের জন্য Retraining আবশ্যক। | রিট্রেনিং ছাড়াই নতুন অবজেক্ট খোঁজা সম্ভব। |

## ২. Grounding DINO Text Prompting Types

Grounding DINO-তে অবজেক্ট চেনার জন্য ৩ ধরনের টেক্সট প্রম্পট ব্যবহার করা যায়:

1. **Single Category Prompt:** `"dog."`
2. **Multi-category Prompt:** `"dog. person. car."` *(ডট দিয়ে প্রতিটি ক্লাস আলাদা করতে হয়)*
3. **Descriptive / Phrase Prompt:** `"white dog lying on the street."`

> **Note:** টেক্সটের নির্দিষ্ট অংশের সাথে ছবির নির্দিষ্ট অঞ্চল (Region) মেলানোর প্রক্রিয়াকে **Grounding** বলা হয়।

### Model Output Structure

মডেল থেকে মূলত ৩টি বিষয় আউটপুট হিসেবে পাওয়া যায়:

```python
{
    "boxes": ...,   # Object Location: [x1, y1, x2, y2]
    "labels": ...,  # Matched Text Tokens
    "scores": ...,  # Token-to-Region Matching Scores
}

```

## ৩. Dual Thresholding Mechanism

Grounding DINO-তে প্রিডিকশন ফিল্টার করার জন্য দুটি থ্রেশহোল্ড ব্যবহার করা হয়:

```
                  ┌──────────────────────┐
                  │ candidate box score  │
                  └──────────┬───────────┘
                             │
              ┌──────────────┴──────────────┐
              ▼                             ▼
   Score > box_threshold        Score > text_threshold
   ─────────────────────        ──────────────────────
    Candidate Box সংসংরক্ষিত হবে   Box-এর Label নির্ধারণ করা হবে

```

| Parameter | দায়িত্ব |
| --- | --- |
| **`box_threshold`** | নির্ধারণ করে কোন ক্যান্ডিডেট বক্সগুলো ফাইনাল আউটপুটে রাখা হবে। (যে কোনো একটি টোকেনের সর্বোচ্চ স্কোর এর চেয়ে বেশি হতে হয়)। |
| **`text_threshold`** | রাখা ফিল্টারকৃত বক্সটির লেবেল তৈরির জন্য কোন কোন টেক্সট টোকেনগুলো অন্তর্ভুক্ত হবে তা ঠিক করে। |

### একটি গাণিতিক উদাহরণ:

* **Token Scores:** `white → 0.18`, `dog → 0.61`
* **Threshold Settings:** `box_threshold = 0.35`, `text_threshold = 0.25`

**ফলাফল:**

* **Box Status:** রাখা হবে (কারণ সর্বোচ্চ স্কোর $0.61 > 0.35$)।
* **Label:** শুধুমাত্র **"dog"** (কারণ `white`-এর স্কোর $0.18$, যা $0.25$-এর নিচে)।

> **Warning:** এখানে স্কোর `0.61` মানেই মডেলের অনুমান শতভাগ সঠিক বা ৬১% নিখুঁত—এমন সরাসরি সিদ্ধান্ত নেওয়া ভুল। এটি মূলত একটি আপেক্ষিক ম্যাচিং স্কোর।

## ৪. Image Processing & Box Coordinate Conversions

### Coordinate Target Size Formatting

PIL Image থেকে সাইজ নেওয়ার সময় ডায়মেনশন অর্ডারের বিষয়ে সতর্ক থাকতে হবে:

```python
# PIL Image size returns -> (width, height)
# Target sizes requires -> (height, width)

target_sizes = [(image.height, image.width)]

```

> এটি আউটপুট বাউন্ডিং বক্সকে মূল ছবির পিক্সেল স্থানাঙ্কে (Pixel Coordinates) রূপান্তর করতে সাহায্য করে।

### Bounding Box Coordinate System

আউটপুট বক্সের ফরম্যাট: `[x1, y1, x2, y2]`

* $(x1, y1)$: বাউন্ডিং বক্সের উপরের বাম কোণার পিক্সেল স্থানাঙ্ক।
* $(x2, y2)$: বাউন্ডিং বক্সের নিচের ডান কোণার পিক্সেল স্থানাঙ্ক।

**Box Dimension Equation:**


$$\text{Width} = x2 - x1$$

$$\text{Height} = y2 - y1$$

## ৫. Evaluation Dataset Split Strategy

মডেল সঠিক মূল্যায়ন করার জন্য কাস্টম স্প্লিট ব্যবহার করা হয়:

* **Calibration Split (২০টি ছবি):** Day 1–4 এর জন্য টেক্সট প্রম্পট এবং থ্রেশহোল্ড টিউন বা ক্যালিব্রেট করার কাজ ব্যবহৃত হয়।
* **Test Split (২০টি ছবি):** Day 5-এর চূড়ান্ত মূল্যায়নের (Final Evaluation) জন্য ব্যবহৃত হয়।
* **Negative Images Inclusion:** প্রতি স্প্লিটে নির্বাচিত ৫টি ক্লাসের কোনো অ্যানোটেশন ছাড়া **২টি নেগেটিভ ছবি** রাখা হয়—যাতে মডেল ভুল জায়গায় অবজেক্ট ডিটেক্ট করে কি না (Hallucination / False Positives) তা পরীক্ষা করা যায়।

# Q&A Note

### Q1: আগের fixed-class YOLO ও Grounding DINO-তে class নির্বাচন করার পার্থক্য কী? Open-vocabulary কি সব object detect করার নিশ্চয়তা?

* **Class নির্বাচন:** আগের fixed-class YOLO-তে কেবল মডেলটির প্রশিক্ষণের সময় নির্দিষ্ট করে দেওয়া কয়েকটি ক্যাটাগরি (যেমন COCO ডেটাসেটের ৮০টি ক্লাস) সনাক্ত করা যেত। অন্যদিকে, Grounding DINO-তে কোনো Retraining ছাড়াই টেক্সট প্রম্পটের (Text Prompt) মাধ্যমে যেকোনো উন্মুক্ত শব্দ বা বর্ণনামূলক বাক্যাংশ দিয়ে ফ্ল্যাক্সিবলভাবে ক্লাস নির্বাচন করা যায়।
* **Open-Vocabulary নিশ্চয়তা:** Open-vocabulary মানেই সব অবজেক্ট শনাক্ত করার শতভাগ নিশ্চয়তা নয়। মডেলটি অপ্রচলিত শব্দ, জটিল বা অস্পষ্ট প্রম্পট, কম আলো বা ছোট অবজেক্টের ক্ষেত্রে ব্যর্থ হতে পারে।

### Q2: Box threshold 0.35, text threshold 0.25; token scores white=0.18, dog=0.61। Box থাকবে কি, কোন token label-এ থাকবে? শুধু box threshold 0.70 করলে কী হবে?

* **Box ও Label:** যেহেতু সর্বোচ্চ টোকেন স্কোর `dog` ($0.61$), যা `box_threshold` ($0.35$) এবং `text_threshold` ($0.25$) উভয় অপেক্ষা বড়, তাই বক্সটি **থাকবে**। আর `white`-এর স্কোর ($0.18$) টেক্সট থ্রেশহোল্ডের কম হওয়ায় লেবেলে শুধু **`dog`** থাকবে।
* **Threshold 0.70 করলে:** বক্স থ্রেশহোল্ড বাড়িয়ে $0.70$ করা হলে $0.61$ স্কোরের এই বক্সটি ফিল্টার আউট হয়ে যাবে এবং স্ক্রিনে কোনো বাউন্ডিং বক্স আউটপুট আসবে না।

### Q3: ছবির width 640, height 426। সঠিক target_sizes কী? xyxy format-এ x2, y2 কি width ও height?

* **Target Sizes:** মডেলের বাউন্ডিং বক্সকে মূল ছবির পিক্সেল ফরম্যাটে রূপান্তর করার জন্য সঠিক `target_sizes` হবে **`[(426, 640)]`** বা `[(height, width)]` ফরম্যাট। (PIL-এর `width, height`-এর উল্টো)।
* **x2, y2:** `xyxy` ফরম্যাটে $(x_1, y_1)$ হলো বাউন্ডিং বক্সের উপরের-বাম কোণ এবং $(x_2, y_2)$ হলো নিচের-ডান কোণের পিক্সেল স্থানাঙ্ক (Coordinates)। এগুলো সরাসরি ছবির পুরো width বা height নির্দেশ করে না; বরং বক্সের শেষ সীমানা প্রকাশ করে। বক্সের Width ও Height বের করার নিয়ম হলো: $\text{Width} = x_2 - x_1$ এবং $\text{Height} = y_2 - y_1$।

### Q4: `fire hydrant.` prompt-এ zero boxes পাওয়া কেন program failure নয়? একটি box এলে কী দেখে false positive বলবেন?

* **Zero Boxes পাওয়া:** ইনপুট ছবিতে যদি কোনো ফায়ার হাইড্র্যান্ট না থাকে, তবে $0$ টি বক্স পাওয়া মোটেও প্রোগ্রাম ফেইলিয়র নয়, বরং এটি মডেলের একটি সঠিক আচরণ। ইমেজ এবং প্রম্পটের সমন্বয়কে যদি কোনো বস্তুর উপস্থিতি বা অনুপস্থিতির প্রশ্ন হিসেবে বিবেচনা করা হয়, তবে এটিকে একটি **True Negative** সিদ্ধান্ত বলা যায়। *(তবে সাধারণ অবজেক্ট ডিটেকশনের Precision/Recall হিসাবের ক্ষেত্রে সাধারণত TN হিসাব করা হয় না; সেখানে কেবল TP, FP ও FN বিবেচনা করা হয়।)*
* **False Positive বিচার:** যদি ছবিতে ফায়ার হাইড্র্যান্ট না থাকা সত্ত্বেও কোনো বাউন্ডিং বক্স প্রেডিক্ট হয়, অথবা প্রেডিক্ট করা বক্সটি ফায়ার হাইড্র্যান্ট ভিন্ন অন্য কোনো ভুল বস্তুকে ঘিরে থাকে, তবে সেটিকে **False Positive** বলা হবে।

### Q5: Day 2-এর threshold বেছে নিতে final test ছবিগুলো বারবার দেখা কেন ঠিক নয়?

* ফাইনাল টেস্ট সেটের ছবিগুলো বারবার দেখে থ্রেশহোল্ড টিউন বা পরিবর্তন করলে ইভালুয়েশনে **Data Leakage (তথ্য ফাঁস)** ঘটে এবং টেস্ট স্কোর অপ্রয়োজনীয়ভাবে অতিরিক্ত আশাবাদী (Optimistic) বা কৃত্রিমভাবে ভালো হয়ে যায়।
* যদিও এতে মডেলের মূল ওয়েট (Model Weights) পরিবর্তিত হয় না, তবুও থ্রেশহোল্ড টিউন করার কারণে টেস্ট স্কোর দিয়ে ভবিষ্যতের কোনো নতুন বা অনভিজ্ঞ ডেটাতে মডেলের প্রকৃত পারফরম্যান্স নিরপেক্ষভাবে অনুমান করা কঠিন হয়ে পড়ে। *(তাই সবসময় ক্যালিব্রেশন বা ভ্যালিডেশন সেটে থ্রেশহোল্ড নির্বাচন করা উচিত।)*
