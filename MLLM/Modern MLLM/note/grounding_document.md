১. 100% usable box মানে 100% raw JSON compliance নয়। প্রথম output-এ Markdown fences ছিল; আগে থেকে নির্ধারিত cleanup-এর পর parser box গ্রহণ করেছে।

২. 0–1000 coordinate scale আমাদের Qwen3-VL workflow-এর convention। সব VLM বা সব Qwen version-এর জন্য একই ধরে নেবে না।

৩. IoU < 0.5 হলো আমাদের failure নির্ধারণের নিয়ম। এর কারণ হতে পারে wrong object অথবা inaccurate boundary; কম IoU একাই কারণটি বলে না।


**Q1: GT box [100, 50, 200, 150] যদি xywh হয়, তার xyxy কত?**

**Ans:** `xywh` বলতে বোঝায় `[x_min, y_min, width, height]` এবং `xyxy` হলো `[x_min, y_min, x_max, y_max]`।

* $x_{max} = x_{min} + width = 100 + 200 = 300$
* $y_{max} = y_{min} + height = 50 + 150 = 200$
* **চূড়ান্ত `xyxy` বক্স:** `[100, 50, 300, 200]`

**Q2: Original image 800 × 600; normalized box [100, 200, 600, 800] হলে pixel box কত?**

**Ans:** ভিশন-ল্যাঙ্গুয়েজ মডেলগুলোতে নরমালাইজড কোঅর্ডিনেট সাধারণত $0$ থেকে $1000$ স্কেলে থাকে। ছবির সাইজ $800 \times 600$ (Width = 800, Height = 600) হলে:

* $x_1 = (100 / 1000) \times 800 = 80$
* $y_1 = (200 / 1000) \times 600 = 120$
* $x_2 = (600 / 1000) \times 800 = 480$
* $y_2 = (800 / 1000) \times 600 = 480$
* **চূড়ান্ত পিক্সেল বক্স:** `[80, 120, 480, 480]`

**Q3: JSON ও coordinates বৈধ হলেও grounding ব্যর্থ হতে পারে কেন?**

**Ans:** দুটি মূল কারণে এটি হতে পারে:

1. **IoU (Intersection over Union) থ্রেশহোল্ড:** মডেলের প্রেডিক্ট করা বক্স এবং আসল গ্রাউন্ড ট্রুথ (GT) বক্সের ওভারল্যাপ যদি নির্দিষ্ট মাত্রার চেয়ে কম হয় (সাধারণত IoU < 0.5), তবে কোঅর্ডিনেট বৈধ হলেও গ্রাউন্ডিং ফেইল করবে।
2. **ভুল অবজেক্ট শনাক্তকরণ:** মডেলটি হয়তো বৈধ কোঅর্ডিনেট দিয়েছে যা ছবির ভেতরেরই কোনো জায়গার, কিন্তু আপনি যে অবজেক্টটি খুঁজছেন, মডেল সেটি বাদ দিয়ে সম্পূর্ণ অন্য কোনো অবজেক্ট মার্ক করেছে।

**Q4: ২০টি query-এর মধ্যে ৩টি invalid output হলে success rate-এর denominator ১৭ হবে, নাকি ২০? কেন?**

**Ans:** Denominator **২০** হবে।

* **কারণ:** Success rate হিসাব করা হয় মডেলকে দেওয়া "মোট টাস্ক বা কুয়েরির" উপর ভিত্তি করে। মডেল যে ৩টি কুয়েরিতে Invalid output দিয়েছে, সেগুলো মডেলের ব্যর্থতা (Failure) হিসেবেই গণ্য হবে। আপনি যদি ১৭ দিয়ে ভাগ করেন, তবে মডেলের ব্যর্থতাগুলো হিসেবের বাইরে চলে যাবে এবং কৃত্রিমভাবে মডেলের পারফরম্যান্স বেশি দেখাবে। তাই প্রকৃত সাকসেস রেট বের করতে সব সময় $\frac{\text{Successful Queries}}{20}$ হিসাব করতে হবে।
